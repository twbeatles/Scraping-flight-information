# Feature Specification: 검색 입력·가격 결과 조회 UX 정리

**Feature Branch**: `001-search-result-ux`

**Created**: 2026-10-12

**Status**: Draft

**Input**: User description: "UI/UX 편의성과 가격 검색 결과 조회 내용을 중점으로, 입력 및 스크래핑된 가격 관련 흐름을 점검하고 사용자 혼동 가능성을 줄이는 리팩토링"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가격을 한 가지 기준으로 믿고 비교한다 (Priority: P1)

사용자는 검색 결과에서 가장 싼 항공편을 찾는다. 정렬, 가격 범위 필터, 최저가 강조가 모두 같은 가격(혜택 반영 비교가)을 기준으로 동작하고, 가격 칸만 봐도 그 기준 가격이 무엇인지 알 수 있어야 한다.

**Why this priority**: 가격 비교가 앱의 핵심 목적이며, 현재는 정렬이 글자 순서로 동작하고 화면마다 기준 가격이 달라 잘못된 항공편을 최저가로 오인할 수 있다.

**Independent Test**: 기본가와 혜택가가 섞인 결과 목록을 표시한 뒤 가격 헤더 정렬·가격 필터·최저가 강조가 같은 순서와 같은 항공편을 가리키는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 200,000원과 1,200,000원 항공편이 있는 결과, **When** 가격 헤더를 눌러 오름차순 정렬, **Then** 200,000원이 먼저 나온다.
2. **Given** 기본가 150,000원·혜택가 110,000원 항공편과 기본가 120,000원 항공편, **When** 결과가 표시됨, **Then** 110,000원 항공편이 맨 위에 있고 최저가로 강조된다.
3. **Given** 위와 같은 결과, **When** 가격 필터 최대값을 11만원으로 설정, **Then** 혜택가 110,000원 항공편이 목록에 남는다.
4. **Given** 혜택가가 기본가보다 싼 항공편, **When** 가격 칸을 봄, **Then** 비교가가 먼저 보이고 기본가가 보조로 함께 표기된다.
5. **Given** 잔여석·경유 컬럼, **When** 헤더로 정렬, **Then** 숫자 크기 순으로 정렬된다.

---

### User Story 2 - 지금 보고 있는 결과가 무엇인지 한눈에 안다 (Priority: P2)

사용자는 결과 표 위에서 어떤 노선·일정·인원의 결과인지, 전체 몇 건 중 몇 건이 보이는지, 최저가가 얼마인지, 결과가 일부 누락됐을 가능성이 있는지 확인한다. 표가 비어 있으면 그 이유(검색 결과 없음 / 필터로 숨김)를 구분해서 안내받는다.

**Why this priority**: 요약 정보가 상태바·진행바·로그 탭에 흩어져 있고 누락 경고는 로그 탭에만 남아, 사용자가 결과를 잘못 해석하기 쉽다.

**Independent Test**: 검색 완료 후 필터를 조정하며 요약 문구와 빈 표 안내 문구가 상황에 맞게 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 124건 결과 중 필터로 87건만 표시, **When** 결과 화면을 봄, **Then** 요약에 노선·일정·인원, "87건 / 전체 124건", 표시 중 최저가가 나온다.
2. **Given** 필터 때문에 0건이 된 상태, **When** 표를 봄, **Then** "필터 조건에 맞는 결과가 없다"는 안내와 전체 건수, 필터 초기화 안내가 나온다.
3. **Given** 검색 자체가 0건, **When** 표를 봄, **Then** 검색 조건 확인을 안내한다.
4. **Given** 결과가 페이지 상한으로 잘린 검색, **When** 결과 화면을 봄, **Then** 요약에 일부 누락 가능 경고가 보인다.
5. **Given** 왕복 결과, **When** 표를 봄, **Then** 가는편/오는편 경유 헤더가 구분되고 소요시간을 표에서 바로 볼 수 있다.
6. **Given** 왕복·혜택가 항공편 행, **When** 행 정보를 복사, **Then** 오는편 시간과 혜택가가 포함된다.

---

### User Story 3 - 필터가 겹치거나 모순되지 않는다 (Priority: P3)

사용자는 경유 조건을 하나의 선택으로 정하고, 실제로 동작하지 않는 입력란을 보지 않는다.

**Why this priority**: 같은 개념의 컨트롤 세 개와 효과 없는 "선호시간" 입력란이 혼동을 만든다.

**Independent Test**: 경유 선택 각 값에 대해 표시되는 항공편의 경유 횟수를 확인하고, 설정의 선호시간이 필터 초기값에 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 경유 선택이 "직항만", **When** 필터 적용, **Then** 경유 0회 항공편만 보인다.
2. **Given** 경유 선택이 "1회 이하", **When** 필터 적용, **Then** 경유 2회 이상 항공편이 숨겨진다.
3. **Given** 설정의 선호 출발 시간이 9~18시, **When** 앱을 시작, **Then** 필터의 가는편 시간이 9~18시로 채워져 있다.
4. **Given** 필터 적용 후, **When** 상태 문구를 봄, **Then** 항공사 구분이 "전체/LCC/FSC" 같은 사용자 용어로 나온다.

---

### User Story 4 - 검색 조건을 실수 없이 빠르게 입력한다 (Priority: P4)

사용자는 출발지·도착지를 한 번에 맞바꾸고, 불가능한 날짜나 인원 조합을 검색 전에 차단·안내받으며, 버튼 문구와 아이콘에서 기능을 바로 이해한다.

**Why this priority**: 입력 오류가 검색 버튼을 누른 뒤에야 모달로 드러나고, 일부 문구·아이콘이 기능과 맞지 않는다.

**Independent Test**: 검색 패널에서 교환 버튼, 날짜 변경, 인원 조합을 조작하고 결과 상태와 안내 문구를 확인한다.

**Acceptance Scenarios**:

1. **Given** 출발 ICN·도착 NRT, **When** 교환 버튼을 누름, **Then** 출발 NRT·도착 ICN이 된다.
2. **Given** 가는 날 10/20·오는 날 10/22, **When** 가는 날을 10/25로 변경, **Then** 오는 날이 10/25 이후로 자동 보정된다.
3. **Given** 날짜 입력란, **When** 오늘 이전 날짜를 고르려 함, **Then** 선택할 수 없다.
4. **Given** 성인 1·유아 2, **When** 검색, **Then** 유아 수가 성인 수를 넘을 수 없다는 안내가 나오고 검색이 시작되지 않는다.
5. **Given** 성인·소아·유아 합계 10명, **When** 검색, **Then** 최대 9명 안내가 나오고 검색이 시작되지 않는다.
6. **Given** 검색이 끝난 뒤, **When** 검색 버튼을 봄, **Then** 검색 전과 같은 문구다.
7. **Given** 편도 선택, **When** 라이트/다크 테마 어느 쪽이든, **Then** 오는 날 입력란이 테마에 맞는 비활성 모양으로 보인다.

### Edge Cases

- 가격이 0이거나 없는 항공편은 정렬 시 맨 뒤로 간다.
- 혜택가가 기본가보다 비싼 경우 비교가는 기본가다.
- 필터 dict에 구 키(`direct_only`, `include_layover`)만 있는 호출도 기존과 같은 결과를 낸다.
- 저장된 프로필·기록·세션에 과거 날짜가 있으면 복원 시 오늘 이후로 보정된다.
- 커스텀 프리셋 공항이 선택된 상태에서 교환해도 값이 유지된다.
- 국내선 모드에서 교환해도 국내 공항 목록이 유지된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 결과 표의 가격·잔여석·경유·소요시간 컬럼은 숫자 값 기준으로 정렬되어야 한다.
- **FR-002**: 결과의 초기 순서, 가격 범위 필터, 최저가 강조는 모두 혜택 반영 비교가를 기준으로 해야 한다.
- **FR-003**: 가격 칸은 비교가를 주 표시로 하고, 혜택가가 적용된 경우 기본가를, 왕복 조합인 경우 구간별 가격을 보조로 표기해야 한다.
- **FR-004**: 저장·내보내기되는 항공편 데이터의 가격 필드 의미(기본가)와 내보내기 컬럼 구성은 바뀌지 않아야 한다.
- **FR-005**: 결과 표 위에 노선, 일정, 인원, 표시/전체 건수, 표시 중 최저가를 보여주는 요약이 있어야 한다.
- **FR-006**: 결과가 페이지 상한으로 잘렸으면 요약에 누락 가능 경고가 표시되어야 한다.
- **FR-007**: 표가 비었을 때 "검색 결과 없음"과 "필터로 모두 숨김"을 다른 문구로 안내해야 한다.
- **FR-008**: 결과 표는 가는편/오는편 경유 헤더를 구분하고 소요시간 컬럼을 제공해야 한다.
- **FR-009**: 행 정보 복사는 비교가, 기본가(다를 때), 왕복 시 오는편 시간을 포함해야 한다.
- **FR-010**: 경유 조건은 하나의 선택(전체 / 직항만 / 1회 이하 / 2회 이하)으로 제공되어야 하며, 필터 값의 기존 키는 유지되어야 한다.
- **FR-011**: 검색 패널에서 결과에 영향이 없는 선호시간 입력란을 제거하고, 필터의 가는편 시간 초기값을 설정의 선호 출발 시간에서 가져와야 한다.
- **FR-012**: 필터 상태 문구는 내부 코드 대신 사용자 용어를 사용해야 한다.
- **FR-013**: 출발지와 도착지를 맞바꾸는 버튼이 있어야 한다.
- **FR-014**: 날짜 입력은 오늘 이전을 선택할 수 없어야 하고, 가는 날이 오는 날보다 늦어지면 오는 날이 자동 보정되어야 한다.
- **FR-015**: 유아 수가 성인 수를 넘거나 총 인원이 9명을 넘으면 검색을 시작하지 않고 이유를 안내해야 한다.
- **FR-016**: 검색 버튼 문구는 검색 전후로 동일해야 하고, 캐시 무시 재조회 버튼은 이름만으로 기능이 드러나야 한다.
- **FR-017**: 세션 저장·불러오기·캘린더 버튼은 기능과 맞는 아이콘을 사용해야 하고, 안내 문구에 제어 문자가 그대로 노출되지 않아야 한다.
- **FR-018**: 편도 선택 시 오는 날 입력란의 비활성 모양은 현재 테마를 따라야 한다.
- **FR-019**: 기존 공개 import 경로와 호환 계약(항공편 결과 형태, 환경설정 스키마, 검색 파라미터 스키마)은 유지되어야 한다.

### Key Entities

- **항공편 결과**: 기본가, 혜택가, 구간별 가격, 시간, 경유, 소요시간 등. 비교가는 기본가와 혜택가 중 낮은 값.
- **필터 조건**: 경유 한도, 항공사 구분, 가는편/오는편 출발 시간대, 가격 범위.
- **결과 요약**: 현재 검색 조건, 표시/전체 건수, 표시 중 최저 비교가, 누락 경고 여부.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 어떤 결과 목록에서도 가격 오름차순 정렬의 첫 행, 최저가 강조 행, 요약의 최저가가 같은 항공편·같은 금액을 가리킨다.
- **SC-002**: 사용자가 탭을 옮기지 않고 결과 화면에서 조회 조건, 표시 건수, 최저가, 누락 경고를 모두 확인할 수 있다.
- **SC-003**: 빈 표가 나타나는 모든 경우에 원인에 맞는 안내가 표시된다.
- **SC-004**: 경유 조건을 정하는 컨트롤이 3개에서 1개로 줄고 모순된 조합을 만들 수 없다.
- **SC-005**: 과거 날짜, 오는 날이 가는 날보다 이른 일정, 허용되지 않는 인원 조합으로는 검색이 시작되지 않는다.
- **SC-006**: 기존 자동 테스트가 모두 통과하고 내보내기 파일의 컬럼이 변경 전과 동일하다.

## Assumptions

- 인원 규칙(유아 ≤ 성인, 총 9명 이하)은 일반적인 항공권 예약 규칙을 따른 것이며 조회 사이트의 실제 제한은 별도로 확인하지 않았다.
- 경유 3회 이상을 따로 고르는 선택지는 두지 않는다. "전체"가 이를 포함한다.
- 설정 대화상자의 선호 시간 항목은 유지하고, 필터 초기값의 출처로 사용한다.
- 다중 목적지·날짜 범위 검색 대화상자의 결과 화면은 이번 범위에 포함하지 않는다.
- 스크래핑 추출 로직과 저장 스키마는 변경하지 않는다.
